# 5. RUST ENGINEERING STANDARD

New or modified Rust code must follow professional engineering practices:

- Stable Rust unless a feature requires otherwise and is documented.
- Idiomatic ownership, borrowing, lifetimes, and explicit resource management.
- No unnecessary unsafe code. Any `unsafe` must be minimal, justified, documented, and reviewed.
- Avoid unbounded threads, queues, caches, memory growth, and task spawning.
- Validate inputs, sizes, ranges, timestamps, and assumptions.
- Use typed errors; avoid panic-based control flow.
- Catch/contain panics at appropriate FFI boundaries.
- Keep deterministic functions deterministic.
- Prefer measured parallelism and batching.
- Consider CPU architecture, compiler settings, reproducible builds, and target compatibility.
- Use formatting, linting, static analysis, and tests where available (`cargo fmt`, `cargo clippy`, `cargo test`).
- Check dependency licenses, known vulnerabilities, maintenance, and unnecessary transitive dependencies.
- Document compiler/toolchain and build steps.

Do not use unsafe memory manipulation, SIMD, lock-free structures, or specialized optimization merely to appear advanced. Add them only when justified and tested.
